Zoho SalesIQ Operations Runbook

OAuth refresh token · bulk delete · FAQ supplement CSV · merge · re-import · Answer Bot testing

This runbook documents the repeatable operational workflow used to reset and reload the Giventa Inc. SalesIQ knowledge base for MOSC (giventainc portal). It complements the architecture guide: Zoho SalesIQ Zobot — MOSC Redesign Knowledge Base Guide and the export script guide: SalesIQ Articles Export — Node Script.

  • F:\project_workspace\mosc-temp — export scripts, CSV files, bulk delete CLI

1. End-to-end workflow (summary)

1. Run event-site-manager locally (OAuth host) 2. Open http://localhost:3000/oauth/zoho/start → Zoho consent → copy ZOHO_REFRESH_TOKEN 3. Save token + client id/secret in .env.local (event-site-manager and/or mosc-temp) 4. From mosc-temp: npm run zobot:bulk-delete-articles -- --dry-run 5. From mosc-temp: npm run zobot:bulk-delete-articles -- --confirm 6. (Optional) Re-export pages: npm run zobot:export-articles 7. Fix titles / patch columns: npm run zobot:fix-import-titles, npm run zobot:patch-import-csv 8. Edit salesiq-faq-supplement.csv for curated Q&A rows 9. npm run zobot:merge-faq-supplement 10. SalesIQ portal → Settings → Resources → Articles → Import CSV 11. Re-train / refresh Answer Bot; test widget questions

2. Prerequisites

RequirementDetails
Zoho API Console client Server-based OAuth client with scopes SalesIQ.articles.READ, SalesIQ.articles.DELETE (and CREATE if you add import via API later). Redirect URIs must include both production and localhost callbacks (see section 3).

3. Obtain ZOHO_REFRESH_TOKEN (event-site-manager)

Step 3a — Register redirect URIs in Zoho API Console

In Zoho API Console, open your client and add these Authorized Redirect URIs (exact match required):

https://www.event-site-manager.com/oauth/zoho/callback
http://localhost:3000/oauth/zoho/callback
Localhost rule: When you visit OAuth from localhost, the callback route automatically uses http://localhost:3000/oauth/zoho/callback — not the production URI in ZOHO_OAUTH_REDIRECT_URI. This prevents the “callback hit production without secrets → 500” failure.
Step 3b — Configure event-site-manager .env.local

Copy from event-site-manager/.env.example and fill in:

ZOHO_CLIENT_ID=your_client_id
ZOHO_CLIENT_SECRET=your_client_secret
ZOHO_OAUTH_REDIRECT_URI=https://www.event-site-manager.com/oauth/zoho/callback
ZOHO_SALESIQ_SCREEN_NAME=giventainc
# Optional: ZOHO_OAUTH_SETUP_SECRET=your-secret

Do not commit .env.local to git.

Step 3c — Start event-site-manager (not mosc-temp)
PowerShell — run OAuth host
Windows single-line
cd F:\project_workspace\event-site-manager; npm run dev

Wait until Next.js is ready (typically http://localhost:3000).

Step 3d — Complete OAuth in browser
  1. Open http://localhost:3000/oauth/zoho/start (add ?key=... if ZOHO_OAUTH_SETUP_SECRET is set).
  2. Sign in to Zoho and approve access (access_type=offline, prompt=consent ensures a refresh token).
  3. After redirect, the success page shows ZOHO_REFRESH_TOKEN=... — copy the full value immediately.
Production OAuth: You can also use https://www.event-site-manager.com/oauth/zoho/start once ZOHO_CLIENT_ID and ZOHO_CLIENT_SECRET are set in AWS Amplify for that app. Localhost is preferred for first-time setup.
Step 3e — CLI fallback (if browser callback failed)

If you have a code= in the URL but the page errored, exchange it manually from mosc-temp:

Exchange authorization code
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:exchange-zoho-code -- --redirect-uri "http://localhost:3000/oauth/zoho/callback" --code "PASTE_CODE_HERE"

The --redirect-uri must match exactly what was used when the code was issued.

Add the refresh token to either repo (bulk-delete loads the first file it finds):

5. Bulk delete existing articles

Scripts live in scripts/zoh-zobot-settings/bulk-delete-salesiq-articles.mjs. They call the SalesIQ Articles REST API using the refresh token.

Always dry-run first
List articles that would be deleted
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:bulk-delete-articles -- --dry-run

Optional filters:

npm run zobot:bulk-delete-articles -- --dry-run --department-id YOUR_DEPT_ID
npm run zobot:bulk-delete-articles -- --dry-run --title-contains "Malankara Orthodox"
npm run zobot:bulk-delete-articles -- --env-file F:/project_workspace/event-site-manager/.env.local --dry-run
Confirm delete
Delete all matching articles
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:bulk-delete-articles -- --confirm
Destructive: --confirm permanently deletes articles. There is no undo. Export a CSV backup first if needed.

7. Add new FAQ / curated articles

Short Q&A articles that Answer Bot retrieves poorly from long scraped pages should go in:

documentation/zoh_zobot_settings/salesiq-faq-supplement.csv

FAQ row format

Use the same columns as the main import CSV:

Site vs curated: Rows backed by mosc-temp.com pages are safe. Curated rows (e.g. individual priests, specific Kalpana numbers not yet on the site) should be updated when official PDFs or directories are published.

Editing tips:

  1. Open salesiq-faq-supplement.csv in Excel or VS Code (UTF-8).
  2. Add a new row at the bottom — wrap fields containing commas in double quotes; escape internal quotes as "".
  3. Run merge (section 8) before import.
  4. Do not duplicate titles already in the main CSV — merge skips existing titles.

9. Import into SalesIQ portal

Portal steps
  1. Sign in to salesiq.zoho.com/giventainc.
  2. Go to Settings → Resources → Articles.
  3. Click Add → Import (or bulk import — match your portal UI).
  4. Upload documentation/zoh_zobot_settings/salesiq-articles-import.csv.
  5. Map columns if prompted (Title, Content, Source URL, Department, etc.).
  6. Confirm import; wait for processing to finish.
  7. Open Settings → Bots → Answer Bot and ensure connected Resources include imported Articles.
  8. If using a hybrid Zobot, verify the Answer Bot card still points at the same brand Resources.
After bulk delete + re-import: Article count should match CSV row count (currently ~272 including 7 FAQ rows). Train or refresh Answer Bot if the portal offers a re-index action.

13. Troubleshooting

SymptomCause / fix
OAuth callback 500 on production ZOHO_CLIENT_ID / ZOHO_CLIENT_SECRET missing in Amplify. Use localhost flow instead, or add secrets and redeploy event-site-manager.
No refresh_token on success page Revoke app in Zoho Accounts → run /oauth/zoho/start again (needs prompt=consent + access_type=offline).
Missing ZOHO_REFRESH_TOKEN in bulk delete Add token to .env.local in mosc-temp or event-site-manager; or pass --env-file.
Answer Bot wrong Catholicos Import FAQ supplement; run zobot:fix-import-titles; re-import. Old Paulose II / Didymos pages still exist but FAQ must win retrieval.
Import “Invalid article language” Use English not en — run zobot:patch-import-csv --language English.
Merge says 0 rows appended FAQ titles already exist in main CSV — change Title in supplement or delete duplicate from main CSV first.
