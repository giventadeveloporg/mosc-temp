Zoho SalesIQ Operations Runbook

OAuth refresh token · bulk upload (REST API) · bulk delete · FAQ supplement CSV · merge · Answer Bot testing

This runbook documents the repeatable operational workflow used to reset and reload the Giventa Inc. SalesIQ knowledge base for MOSC (giventainc portal). Recommended import path: post all articles from salesiq-articles-import.csv using npm run zobot:bulk-upload-articles (SalesIQ Articles REST API). Portal CSV import remains documented as an alternative. This runbook complements the architecture guide: Zoho SalesIQ Zobot — MOSC Redesign Knowledge Base Guide and the export script guide: SalesIQ Articles Export — Node Script.

Repos involved:

  • F:\project_workspace\event-site-manager — hosts OAuth routes (/oauth/zoho/start, /oauth/zoho/callback)
  • F:\project_workspace\mosc-temp — export scripts, CSV files, bulk upload/delete CLI

1. End-to-end workflow (summary)

1. Run event-site-manager locally (OAuth host) 2. Open http://localhost:3000/oauth/zoho/start → Zoho consent (scopes incl. CREATE) → copy ZOHO_REFRESH_TOKEN 3. Save token + client id/secret + SalesIQ IDs in .env.local (mosc-temp and event-site-manager) 4. (Optional reset) npm run zobot:bulk-delete-articles -- --dry-run → --confirm 5. (Optional) Re-export: npm run zobot:export-articles 6. npm run zobot:fix-import-titles → npm run zobot:patch-import-csv → edit salesiq-faq-supplement.csv 7. npm run zobot:merge-faq-supplement 8. npm run zobot:list-portal-ids (verify category / department IDs) 9. npm run zobot:bulk-upload-articles -- --dry-run → --confirm (posts all CSV rows via API) 10. Re-train / refresh Answer Bot; test widget questions

RequirementDetails

3. Obtain ZOHO_REFRESH_TOKEN (event-site-manager)

Step 3a — Register redirect URIs in Zoho API Console

In Zoho API Console, open your client and add these Authorized Redirect URIs (exact match required):

https://www.event-site-manager.com/oauth/zoho/callback
http://localhost:3000/oauth/zoho/callback
Localhost rule: When you visit OAuth from localhost, the callback route automatically uses http://localhost:3000/oauth/zoho/callback — not the production URI in ZOHO_OAUTH_REDIRECT_URI. This prevents the “callback hit production without secrets → 500” failure.
Step 3b — Configure event-site-manager .env.local

Copy from event-site-manager/.env.example and fill in:

ZOHO_CLIENT_ID=your_client_id
ZOHO_CLIENT_SECRET=your_client_secret
ZOHO_OAUTH_REDIRECT_URI=https://www.event-site-manager.com/oauth/zoho/callback
ZOHO_OAUTH_SCOPES=SalesIQ.articles.READ,SalesIQ.articles.CREATE,SalesIQ.articles.DELETE,SalesIQ.departments.READ
ZOHO_SALESIQ_SCREEN_NAME=giventainc
# Optional: ZOHO_OAUTH_SETUP_SECRET=your-secret

ZOHO_OAUTH_SCOPES must include SalesIQ.articles.CREATE for bulk upload. After changing scopes, re-run OAuth (section 3) and replace ZOHO_REFRESH_TOKEN.

Do not commit .env.local to git.

Step 3c — Start event-site-manager (not mosc-temp)
PowerShell — run OAuth host
Windows single-line
cd F:\project_workspace\event-site-manager; npm run dev

Wait until Next.js is ready (typically http://localhost:3000).

Step 3d — Complete OAuth in browser
  1. Open http://localhost:3000/oauth/zoho/start (add ?key=... if ZOHO_OAUTH_SETUP_SECRET is set).
  2. Sign in to Zoho and approve access (access_type=offline, prompt=consent ensures a refresh token).
  3. After redirect, the success page shows ZOHO_REFRESH_TOKEN=... — copy the full value immediately.
Production OAuth: You can also use https://www.event-site-manager.com/oauth/zoho/start once ZOHO_CLIENT_ID and ZOHO_CLIENT_SECRET are set in AWS Amplify for that app. Localhost is preferred for first-time setup.
Step 3e — CLI fallback (if browser callback failed)

If you have a code= in the URL but the page errored, exchange it manually from mosc-temp:

Exchange authorization code
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:exchange-zoho-code -- --redirect-uri "http://localhost:3000/oauth/zoho/callback" --code "PASTE_CODE_HERE"

The --redirect-uri must match exactly what was used when the code was issued.

Editing tips:

9. Bulk upload articles via REST API (recommended)

Script: scripts/zoh-zobot-settings/bulk-upload-salesiq-articles.mjs. Reads salesiq-articles-import.csv and creates each article with:

POST https://salesiq.zoho.com/api/v2/giventainc/articles

Payload fields: title, content (HTML from CSV Content), department_id, category_id, published: true. Titles that are still generic site titles are auto-fixed using the Source URL slug (same logic as zobot:fix-import-titles).

Prerequisites
  1. ZOHO_REFRESH_TOKEN in .env.local with scope SalesIQ.articles.CREATE (re-run OAuth in section 3 if you only had READ/DELETE before).
  2. CSV ready: npm run zobot:fix-import-titles and npm run zobot:merge-faq-supplement completed.
  3. Category General (or your target category) exists in the portal — create in SalesIQ UI if missing.
  4. Optional: set ZOHO_SALESIQ_CATEGORY_ID and ZOHO_SALESIQ_DEPARTMENT_ID in .env.local, or let the script resolve by name (MOSC Connect / General).
Step A — List portal IDs (optional)
Print category and department IDs
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:list-portal-ids

Script: scripts/zoh-zobot-settings/list-salesiq-portal-ids.mjs. Copy IDs into ZOHO_SALESIQ_CATEGORY_ID / ZOHO_SALESIQ_DEPARTMENT_ID. Department ID also appears on each category from GET /api/v2/{screen}/articlecategories when SalesIQ.departments.READ is unavailable.

Step B — Dry-run (preview)
Preview rows without POST
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:bulk-upload-articles -- --dry-run

Shows how many rows would be created, resolved category/department IDs, and any rows skipped (duplicate title already in portal).

Step C — Smoke test (5 articles)
Create first 5 articles
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:bulk-upload-articles -- --confirm --limit 5

Verify new articles in SalesIQ → Resources → Articles before the full run.

Step D — Full upload (~272 articles)
POST all CSV rows (default delay 400 ms between requests)
Windows single-line
cd F:\project_workspace\mosc-temp; npm run zobot:bulk-upload-articles -- --confirm

Expect ~6–8 minutes for ~272 rows. Console reports created / failed counts.

Resume after interruption:

npm run zobot:bulk-upload-articles -- --confirm --start 50 --limit 20
npm run zobot:bulk-upload-articles -- --confirm --start 70

Other flags:

npm run zobot:bulk-upload-articles -- --confirm --input documentation/zoh_zobot_settings/salesiq-articles-import.csv
npm run zobot:bulk-upload-articles -- --confirm --department-name "MOSC Connect" --category-name General
npm run zobot:bulk-upload-articles -- --confirm --department-id 1171471000000002013 --category-id 1171471000000002104
npm run zobot:bulk-upload-articles -- --confirm --delay-ms 600
npm run zobot:bulk-upload-articles -- --confirm --no-skip-existing
npm run zobot:bulk-upload-articles -- --env-file F:/project_workspace/event-site-manager/.env.local --confirm
CSV row count vs portal count: The CSV has ~272 data rows. A prior portal-only import may have created fewer articles (e.g. 97) if Validate failed or titles were generic. Bulk delete removes all articles returned by the API, not “97 max.” After API upload, zobot:bulk-delete-articles -- --dry-run should list ~272 (or slightly more if manual articles exist).
After upload: Open Settings → Bots → Answer Bot, ensure Resources include Articles, then re-train or refresh the knowledge base if the portal offers it.

10. Alternative: portal CSV import

Portal steps (if you cannot use API CREATE scope)

Use this only when OAuth cannot include SalesIQ.articles.CREATE. Detailed mapping tables live in the main guide — Section 7.

  1. Sign in to salesiq.zoho.com/giventainc.
  2. Create article Categories matching CSV Category column before import.
  3. Go to Settings → Articles (Settings sidebar) → Add → Import.
  4. Upload documentation/zoh_zobot_settings/salesiq-articles-import.csv.
  5. On Add Articles: map columns 1:1; set status to Publish; run Validate, then finish import.
  6. Connect imported Articles to Answer Bot (section 11).
Known issues with portal import: Generic titles, category mismatches, and language code en vs English — run zobot:fix-import-titles and zobot:patch-import-csv --language English before uploading.

14. Troubleshooting

SymptomCause / fix
OAuth callback 500 on production ZOHO_CLIENT_ID / ZOHO_CLIENT_SECRET missing in Amplify. Use localhost flow instead, or add secrets and redeploy event-site-manager.
No refresh_token on success page Revoke app in Zoho Accounts → run /oauth/zoho/start again (needs prompt=consent + access_type=offline).
Missing ZOHO_REFRESH_TOKEN in bulk delete/upload Add token to .env.local in mosc-temp or event-site-manager; or pass --env-file.
Invalid OAuthScope on upload Refresh token lacks SalesIQ.articles.CREATE. Add scope to ZOHO_OAUTH_SCOPES, restart event-site-manager, re-run http://localhost:3000/oauth/zoho/start, replace ZOHO_REFRESH_TOKEN.
fetch failed / UNABLE_TO_VERIFY_LEAF_SIGNATURE TLS interception on your network. Set ZOHO_INSECURE_TLS=1 in .env.local (dev only), or fix corporate root CA in Node.
Upload skips all rows (“already exists”) Portal still has articles with same titles. Run zobot:bulk-delete-articles -- --confirm or use --no-skip-existing (may duplicate titles).
Delete dry-run shows 97 but CSV has 272 97 was articles in the portal before delete; 272 is local CSV rows. Portal CSV import often imported fewer rows. API upload targets all CSV rows.
Answer Bot wrong Catholicos Merge FAQ supplement; run zobot:fix-import-titles; run zobot:bulk-upload-articles -- --confirm; re-train Answer Bot.
Import “Invalid article language” (portal only) Use English not en — run zobot:patch-import-csv --language English.
Merge says 0 rows appended FAQ titles already exist in main CSV — change Title in supplement or delete duplicate from main CSV first.
