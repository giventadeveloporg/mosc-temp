Full-Site E2E Testing Guide (TestSprite)

This guide covers the inventory-driven Playwright / TestSprite E2E loop for MOSC: route inventory generation, admin + public smoke crawls, demo-tenant CRUD, and MOSC tree crawls. Prefer tenant tenant_demo_002 for safe mutations. Primary scripts live under TestSprite/.

Also see the short markdown summary: TestSprite/E2E_FULL_README.md and run log TestSprite/reports/LOOP_LOG.md.

1. Prerequisites

Before you run
  • Node.js 18+ and npm install at repo root
  • Playwright Chromium: npm run test:install-playwright
  • App running (e.g. npm run dev) and backend API reachable
  • Copy TestSprite/admin-tests/auth.json.example → TestSprite/admin-tests/auth.json (ADMIN email/password for the tenant)
  • Prefer NEXT_PUBLIC_TENANT_ID=tenant_demo_002. If your local tenant differs, set E2E_ALLOW_ANY_TENANT=1
Windows tip: Prefer cmd /c "set VAR=value&& node ..." for env vars. PowerShell $env:... can fail to surface script output with some npm wrappers.

10. Reports & safety

📊 Outputs
  • Coverage JSON: TestSprite/reports/coverage-*.json
  • Coverage HTML (pass/fail, wall clock, per-module timings): TestSprite/reports/coverage-*.html — written automatically with JSON; regenerate with npm run test:coverage:html
  • Append-only log: TestSprite/reports/LOOP_LOG.md
  • Inventory: TestSprite/generated/route-inventory.json
  • Contact form suite: npm run test:contact-form → /mosc-redesign/contact-form-email + send-html API validation (no live email)
  • Legacy admin HTML only: TestSprite/admin-tests/admin-test-report.html (comprehensive suite — not under reports/)
Report rotation: each harness suite write keeps the newest E2E_REPORT_KEEP files per suite (default 5) and deletes coverage files older than E2E_REPORT_MAX_AGE_DAYS (default 5). LOOP_LOG.md is kept. Folder is gitignored.
Global consolidated report: after the recommended ladder (or npm run test:coverage:consolidated), open TestSprite/reports/coverage-global-latest.html for overall SUCCESS/FAILED plus every suite’s pass/fail and links to module HTML. Timestamped copy: coverage-global-consolidated-<stamp>.html.
If you chain Node steps with all && and comprehensive admin exits non-zero (e.g. Membership Plans fail), CRUD and smoke never run — so nothing new appears under TestSprite/reports/. Use & between Node steps (see §11).
Safety rules: mutate only [E2E] copies; no live Stripe charges; auth-gated public redirects are recorded as pass; MOSC crawls pace requests to avoid saturating the Next.js dev server.

11. Recommended command: public + admin + mosc-redesign (tenant_demo_002)

Use this command for the standard scoped E2E run on tenant_demo_002: core site pages (http://localhost:3000), full admin including home-button click-through (/admin), and every page under /mosc-redesign, while excluding /mosc and /mosc-old. This is the canonical copy-paste command for that profile.
What this command does

One cmd /c line sets the demo tenant env vars, points Playwright at http://localhost:3000, then runs five steps in order. Env vars are joined with &&; Node steps are joined with & so CRUD and smoke still run even if the comprehensive admin suite exits non-zero (failed assertions).

  1. generate-route-inventory.js — rebuilds TestSprite/generated/route-inventory.json from all page.tsx files so smoke knows which URLs exist.
  2. comprehensive-admin-test-suite.js — deeper admin UI checks (forms, tables, key interactions) beyond a simple page load.
  3. admin-crud-demo-tenant-suite.js — create / update / delete [E2E] sample rows on the demo tenant.
  4. run-inventory-smoke-crawl.js --kind=admin,public,mosc-redesign — visits every inventory route for those three kinds only (core public + all /admin routes + admin-home buttons + all /mosc-redesign pages). Omitting mosc and mosc-old from --kind excludes those trees.
  5. write-consolidated-coverage-report.js — writes coverage-global-latest.html (overall SUCCESS/FAILED + per-suite rollup + merged detail tables).
Recommended for documentation / daily use: copy the command block below. Do not use an all-&& Node chain for this profile — a failing comprehensive suite would skip CRUD and smoke.
Tenant env vars: NEXT_PUBLIC_TENANT_ID, E2E_TENANT_ID, and E2E_EXPECTED_TENANT are all set to tenant_demo_002 so the harness hard-checks the demo tenant (do not set E2E_ALLOW_ANY_TENANT=1 for this profile). Restart the Next.js app with the same tenant in .env so the UI serves demo data.
Prerequisites still apply: app running on port 3000, TestSprite/admin-tests/auth.json present, Playwright browsers installed.

Step Script Covers
1 generate-route-inventory.js Fresh route list
2 comprehensive-admin-test-suite.js Fuller admin UI assertions
3 admin-crud-demo-tenant-suite.js [E2E] CRUD on tenant_demo_002

12. HTML reports & contact-form

Global rollup + optional contact-form suite
Global report: the §11 ladder ends with write-consolidated-coverage-report.js, which writes TestSprite/reports/coverage-global-latest.html (and a timestamped coverage-global-consolidated-*.html). It merges the latest harness suite JSON (CRUD, smoke, etc.) into one overall SUCCESS/FAILED view with per-suite rows and the same detail tables as module reports.
Contact-form deep suite is optional — run separately with npm run test:contact-form (TestSprite/sanity-tests/run-contact-form-email-tests.js (form fields + send-html API 400/405; no live email). The §11 smoke crawl still visits /mosc-redesign/contact-form-email as a page load.
  • Module reports remain as coverage-<suite>-<stamp>.html (e.g. smoke-admin+public+mosc-redesign).
  • Legacy comprehensive admin still writes only TestSprite/admin-tests/admin-test-report.html (not merged into the harness global JSON unless you add a harness adapter later).
Where to find the HTML report

Every harness suite that uses CoverageTracker writes both JSON and HTML under TestSprite/reports/.

Artifact Path / pattern What it shows
Coverage JSON TestSprite/reports/coverage-*.json Machine-readable pass/fail list and timings
Coverage HTML TestSprite/reports/coverage-*.html Overview: totals, wall clock, per-module durations, failures, all results — open in a browser
Smoke (scoped ladder) coverage-smoke-admin+public+mosc-redesign-<stamp>.html HTML for the inventory smoke step of §11
Global consolidated coverage-global-latest.html (+ coverage-global-consolidated-<stamp>.html) Overall SUCCESS/FAILED + every suite’s pass/fail + merged detail tables
Contact-form suite (optional) coverage-contact-form-email-<stamp>.html HTML for the deep contact-form / send-html checks
Loop log TestSprite/reports/LOOP_LOG.md Append-only summary lines pointing at JSON + HTML paths
Console hint: when a suite finishes you should see [harness] HTML report: …\TestSprite\reports\coverage-….html next to the JSON path. Open that .html file in Chrome/Edge.
JSON-only older reports: if you have a coverage-*.json from before HTML generation existed, regenerate with: npm run test:coverage:html (or pass a specific JSON path to node TestSprite/tools/coverage-json-to-html.js …).
