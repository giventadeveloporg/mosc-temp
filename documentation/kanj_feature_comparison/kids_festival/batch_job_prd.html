v1 position: Batch is not required for core Kids Festival registration. Registration is synchronous via backend REST + Next.js Stripe webhook (frontend_prd.html). Do not block P0–P3 on batch work.

When email or bulk notification is needed, follow existing donation / manual-payment batch patterns. Next.js or Spring Boot triggers batch HTTP endpoints; batch project does not host Stripe webhooks.

4. Integration flow

Parent pays (Stripe) → Next.js webhook confirms registrations (sync)
    → [optional] POST batch kids-festival-registration-email
    → EmailService sends template

Admin publishes results → Admin UI or boot
    → [optional] POST batch kids-festival-results-published-email

5. Out of scope (batch v1)

  • Capacity waitlist processor
  • Schedule PDF generation
  • Soundtrack upload / judging workflow
  • Stripe webhook handling in batch project
  • Replacing sync registration API

6. Environment & operations

  • Batch service base URL configured in Next.js / boot (same as existing donation batch calls)
  • Email templates stored per tenant (align with existing template ID conventions)
  • Idempotent job triggers: safe to retry confirmation email with same registrationIds
