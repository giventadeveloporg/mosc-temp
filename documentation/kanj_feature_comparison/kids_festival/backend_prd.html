6. Security & tenancy

  • JWT Bearer (existing stack); tenant from TenantContextFilter and X-Tenant-ID header (frontend proxy sends per Next.js rules)
  • Parent: POST/PATCH/DELETE on child profiles and registrations only when registered_by_user_profile_id or owning parent matches authenticated profile
  • Admin: catalog CRUD, results entry, publish (is_published), settings
  • Public read: published results, active competitions, content blocks (no auth required at proxy; backend may still require JWT for list endpoints — align with existing public event patterns)
