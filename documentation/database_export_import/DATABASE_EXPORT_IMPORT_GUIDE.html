5. Comment out pg_dump header lines

⚠️ Required before import in some clients: Generated files may contain lines starting with pg_dump (metadata comments). PostgreSQL will error if those run as SQL.
  1. Open corrected_event_media_inserts.ordered.sql (or the _PROD variant) in your editor.
  2. Ctrl+H (Find and Replace).
  3. Find: pg_dump
  4. Replace: -- pg_dump
  5. Replace all (review matches so you do not comment legitimate data values).

6. Import the SQL file

Prerequisites
  • Target database has schema applied (empty tables).
  • Import into a truncated or fresh database to avoid duplicate primary-key errors.
  • For circular FK warnings on user_profile / event_details, consider wrapping import with: SET session_replication_role = 'replica'; … import … SET session_replication_role = 'origin';
Import via psql (recommended)
🔧 Customize parameters:
docker exec -i a6fb865ce8e0 psql -U event_site_admin -d event_site_manager_db < corrected_event_media_inserts.ordered.sql
Windows single-line:
docker exec -i a6fb865ce8e0 psql -U event_site_admin -d event_site_manager_db < corrected_event_media_inserts.ordered.sql
DBeaver: Open the SQL file, set statement delimiter to ;, enable continue on error if available, and execute against an empty schema. Stopping on the first FK error leaves later tables empty.

7. Sync sequences after import

After manual INSERTs with explicit IDs, PostgreSQL sequences may still point at low values. Run sync_sequence_after_inserts.sql so the next auto-generated primary key starts above the highest imported ID (typically MAX(id) + 50).

Canonical paths:

  • code_html_template/SQLS/Current_Sqls/sync_sequence_after_inserts.sql (this repo)
  • E:\project_workspace\malayalees-us-site-boot\src\main\resources\sqls\sync_sequence_after_inserts.sql (backend boot project)
📊 Run order
  1. Apply schema SQL
  2. Run ordered INSERT file
  3. Run sync_sequence_after_inserts.sql in the same database

9. Troubleshooting partial imports

SymptomLikely causeFix
Some tables have fewer rows than export Tables were in “extra tables” block at EOF (wrong FK order) before script fix Regenerate with updated reorder_sql_inserts_final.cjs; confirm Extra tables: none
Import stops mid-file DBeaver stops on first error (FK violation, duplicate PK) Use psql, continue-on-error, or fix order; start from empty DB
official_document_year_bundle empty Was ~line 6182 before fix; child rows failed first Now ~line 339 (after official_document_category)
Spring Batch tables incomplete batch_job_instance etc. were after thousands of log rows Batch chain now ordered: instance → execution → context → params → step → step_context → log
Duplicate key on re-import Target DB not empty Truncate tables or use fresh schema before import
Alternative import options:
  • Option B: psql -v ON_ERROR_STOP=0 to log errors and continue
  • Option C: DBeaver — delimiter ;, continue on error, empty target
