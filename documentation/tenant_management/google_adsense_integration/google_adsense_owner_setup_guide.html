Google AdSense — Application Owner Setup Guide

Audience: Platform / application owner operating multiple satellite domains  |  Companion doc: google_adsense_integration_prd.html (technical integration)  |  Updated: June 2026

This guide explains how to configure Google AdSense when you run a multi-tenant platform with many satellite sites. It covers step-by-step work in the Google AdSense dashboard and how to map results into Tenant Settings → Integrations in your admin app.

You can choose either one shared Publisher ID (all ad revenue to the application owner) or per-tenant Publisher IDs (each organization keeps its own revenue). The application already stores AdSense settings per tenant row in tenant_settings.

1. Choose your monetization model

Google pays the Google account that owns the Publisher ID (ca-pub-XXXXXXXXXXXXXXXX). Your application reads that ID from each tenant’s settings and injects it into ad slots on that tenant’s public site.

Model Who gets paid Google AdSense accounts Best for
A — Shared Publisher ID Application owner (one organization) One AdSense account; all satellite domains added as sites under that account You operate the platform and want all satellite ad revenue in your AdSense account
B — Per-tenant Publisher ID Each tenant organization One AdSense account per tenant (each tenant signs up with Google) Tenants are independent orgs that keep their own ad revenue; you only provide the tech
Hybrid Mix: owner on some tenants, tenants on others Owner account + optional tenant accounts Owner monetizes default satellites; premium or partner tenants use their own IDs

Recommendation for application owners: If you want revenue from all satellite domains to flow into your bank account, use Model A (Shared Publisher ID). Create one AdSense account under your company, add every satellite domain as a site in Google, use the same ca-pub-... on every tenant’s Integrations tab, and create separate ad units per domain (or per region) for reporting.

Legal / policy: Tenants whose sites display your Publisher ID should agree in your terms of service that you may monetize their satellite. Per-tenant IDs (Model B) avoid that revenue-sharing question because Google pays the tenant directly.

2. Model A — Shared Publisher ID (owner receives all revenue)

Centralized monetization — one ca-pub- for every tenant

All satellites share your Publisher ID. Google aggregates earnings in your AdSense payments. You can still use different ad unit slot IDs per tenant or per domain for analytics.

Architecture

  • One Google AdSense account (your company email).
  • One Publisher ID: e.g. ca-pub-1234567890123456.
  • Many sites in AdSense — one per satellite domain (e.g. www.mosc-temp.com, www.partner-org.com).
  • Many ad units — typically 3+ per domain (sidebar, between sections, footer).
  • Per tenant in admin: Enable AdSense, paste the same Publisher ID, paste placements JSON with that domain’s slot IDs.

Owner setup summary

  1. Create or use your company AdSense account (Section 5).
  2. Copy your Publisher ID from Account → Settings → Account information.
  3. For each satellite domain: add site in AdSense, wait for approval, deploy ads.txt with your pub-... line.
  4. For each domain: create display ad units; record slot IDs per region.
  5. For each tenant row in admin: Integrations → Enable → same ca-pub-... → placements JSON with that tenant’s slot IDs → Save.

3. Model B — Per-tenant Publisher ID (tenant receives revenue)

Decentralized monetization — each tenant uses their own ca-pub-

Each organization creates its own Google AdSense account. You store their Publisher ID and slot IDs only on their tenant settings row. Google pays them directly; you do not receive their ad earnings.

Tenant responsibilities

  1. Tenant signs up at google.com/adsense with their organization’s Google account.
  2. Tenant adds their satellite domain as a site and completes verification / approval.
  3. Tenant creates ad units and provides you (or enters in admin) Publisher ID + slot IDs.
  4. Tenant deploys or requests ads.txt with their pub-... on their domain.

Your responsibilities as platform owner

  • Grant tenant admins access to Tenant Settings → Integrations (or enter values on their behalf).
  • Store their ca-pub-... only on their tenant row — never your owner ID on their tenant if they should receive payment.
  • Leave AdSense disabled for tenants who have not completed Google approval.

ads.txt conflict: Each domain can only declare one authorized seller line per publisher for a given relationship. If Tenant B uses their own pub-..., that domain’s ads.txt must list their numeric ID, not yours. See Section 7.

4. Hybrid model (mixed)

Some tenants on owner ID, some on tenant ID

The database supports this today: each tenant_settings row has its own google_adsense_publisher_id. No code change is required — only configuration discipline.

Non-monetized (AdSense disabled) N/A Internal, trial, or ad-free tier

5. Google AdSense dashboard (step-by-step)

These steps apply to whichever Google account owns the Publisher ID (yours for Model A, tenant’s for Model B). Menu names may vary slightly; look for Sites, Ads, and Account.

1 Create or open an AdSense account

  1. Go to https://www.google.com/adsense and sign in with the Google account that should receive payments.
  2. Complete signup: country, timezone, payment address, phone verification.
  3. If prompted for an initial site, enter your first satellite domain (you can add more later).
  4. Wait for account and site review (often 24 hours to several days).

2 Find your Publisher ID

  1. In AdSense: Account → Settings → Account information.
  2. Copy Publisher ID — format pub-1234567890123456 or shown as ca-pub-1234567890123456.
  3. For the admin app, always use the ca-pub- form (required by validation).

3 Add each satellite domain as a site

Repeat for every public hostname that will show ads (Model A: all your satellites; Model B: tenant’s domain only).

  1. Sites → Add site (or Manage your sites).
  2. Enter the URL exactly as users visit it (include www if that is canonical).
  3. Submit and wait until status is Ready / approved. Fix policy issues if Google flags content.
  4. Under the site, open ads.txt — Google shows the line you need for that account.

4 Deploy ads.txt on each domain

Google expects:

google.com, pub-1016198353275904, DIRECT, f08c47fec0942fa0

For Model A (shared owner ID on giventa.com), use the line above. For Model B, substitute the tenant’s numeric pub-... ID. See google_adsense_shared_publisher_giventa.html.

  • Use the numeric pub-... (no ca- prefix) in ads.txt.
  • File must be reachable at https://YOUR-DOMAIN/ads.txt (HTTPS, root path).
  • Repository template: public/ads.txt in mosc-temp — update before deploy per domain.
  • In AdSense, use Check for updates on the site’s ads.txt page after deploy.

5 Create display ad units (slot IDs)

For each layout region you use (see PRD region map):

  1. Ads → By ad unit → New ad unit.
  2. Choose Display ads (or responsive display).
  3. Name clearly: e.g. MOSC-TEMP — Sidebar, Partner — Footer strip.
  4. Save and open the unit — copy the data-ad-slot value (digits only, e.g. 1234567890).
  5. Do not paste the full HTML snippet into tenant settings; only the slot ID goes in placements JSON.

6 Optional — Auto ads

This integration uses manual placements (region → slot ID). You do not need to enable Auto ads for the built-in regions. If you turn on Auto ads in Google for a site, you may see extra placements outside your configured regions.

6. Configure each tenant in the admin app

After Google setup, map IDs into the platform (same for Model A or B; only the Publisher ID value changes).

Where to configure

  • Primary admin (all tenants): /admin/tenant-management/settings → edit tenant → Integrations tab
  • Satellite admin: /admin/tenant-management/settings/{id}/edit → Integrations tab

Fields

FieldModel A (owner)Model B (tenant)
Enable Google AdSense On when site approved in Google On when tenant’s site approved
Publisher ID Owner’s ca-pub-... on every monetized tenant Tenant’s ca-pub-... on their row only
Placements JSON Slot IDs for that domain’s ad units Tenant’s slot IDs for their domain

Save workflow

  1. Open Integrations tab.
  2. Toggle Enable Google AdSense.
  3. Enter Publisher ID (must match ^ca-pub-[0-9]+$).
  4. Paste placements JSON (valid object; keys = region IDs).
  5. Save. If homepage is CDN-cached, bump homepageCacheVersion for that tenant.
  6. To stop ads for one satellite only: disable the toggle and save — other tenants unchanged.

7. ads.txt per satellite domain

Modelads.txt contentDeploy note
A — Shared owner ID Same pub-OWNER... on every satellite domain Each Amplify / hosting deploy for that domain must serve the file with owner’s numeric ID
B — Per-tenant ID pub-TENANT... specific to that tenant’s AdSense account That tenant’s domain must not list the owner’s pub ID if tenant is paid
Hybrid Per-domain: owner line OR tenant line matching Integrations Publisher ID Document which domain uses which model before deploy

Current platform note: mosc-temp ships a single static public/ads.txt. For multiple satellites with different Publisher IDs (Model B or Hybrid), you need either separate deployments per domain with the correct file, or a future dynamic ads.txt route per hostname. For Model A (one owner ID), the same line on all domains is correct.

8. Verification checklist

  1. AdSense account approved; each live domain shows Ready under Sites.
  2. https://DOMAIN/ads.txt returns 200 and correct pub-... for that domain’s Publisher ID.
  3. Admin Integrations: AdSense enabled, Publisher ID saved, placements JSON valid.
  4. Public homepage (logged out): ad regions visible where configured; empty regions hidden if slot missing.
  5. Disable AdSense for tenant → ads disappear on that satellite only.
  6. AdSense → Reports: impressions/clicks begin after traffic (may take hours).
  7. EU/UK: implement consent (CMP / GDPR) before enabling in regulated regions.

9. Troubleshooting

SymptomLikely causeAction
Blank ad boxes Site not approved, ads.txt missing, or wrong slot ID Check Sites status, ads.txt URL, slot IDs in JSON
Save fails: invalid Publisher ID Missing ca-pub- prefix or enabled with empty ID Use ca-pub-1234...; or disable AdSense to clear requirement
Revenue goes to wrong party Wrong Publisher ID on tenant row Model A: same owner ID everywhere; Model B: tenant ID only on their row
ads.txt “Not found” in Google File not deployed or HTTP redirect loop Deploy public/ads.txt; verify HTTPS root path
Ads on wrong tenant’s site Tenant settings mixed between rows Verify tenant_id on settings row matches satellite’s NEXT_PUBLIC_TENANT_ID
